# Доработки от 31 августа 2026 года — Dashboard ERP

> **Комментарий для программиста:** внедрите этот HTML в основную ERP-систему.

Готовая точка входа: [`dashboard.html`](dashboard.html). Вкладки «Продажи», «Выручка» и «Выработка» открываются через [`dashboard-report.html`](dashboard-report.html). Для переноса требуется весь комплект файлов из этой папки; отдельно взятый HTML без CSS и JavaScript работать полностью не будет.

## 1. Внедрение в ERP

- Добавить в левое меню основной ERP отдельный пункт `Dashboard`.
- Открывать Dashboard внутри существующей оболочки ERP, сохраняя левое меню, верхнюю панель, профиль пользователя и текущую авторизацию.
- Не изменять существующие разделы ERP и ранее сделанную CRM с лидами.
- Внутри Dashboard оставить четыре вкладки в фиксированном порядке: `Лиды`, `Продажи`, `Выручка`, `Выработка`.
- При переключении вкладок не должны прыгать ширина, положение или высота основных колонок. На всех четырёх экранах используется одна сетка: слева факт, в центре график, справа квота или план.
- Убрать отдельный заголовок `Dashboard` и декоративного котика. Название текущего отчёта показывать только внутри центральной карточки.

## 2. Общие требования к интерфейсу

- Сохранить светлый стиль основной ERP: белые карточки, спокойный светло-серый фон, голубой основной акцент и фиолетовый акцент для услуг.
- Левая и правая панели должны иметь одинаковую ширину на всех вкладках. Центральный график также должен сохранять одинаковую ширину.
- Графики сделать немного компактнее по высоте, чтобы в боковых панелях помещалась необходимая расшифровка без прокрутки всей страницы.
- Ось графика всегда начинается с нуля. Верхняя граница округляется до понятного значения: например, при максимуме 9,1 млн показывать сверху 10 млн.
- Последнюю точку графика не прижимать к правой границе; оставить визуальный отступ.
- На недельных графиках показывать только даты, без подписи дня недели `Чт`.
- Подписи значений не делать чрезмерно жирными и крупными. Сетка, размеры текста и отступы должны быть единообразными во всех отчётах.
- Переключатель периода содержит только `Недели` и `Месяц`.

## 3. Лиды

- При открытии вкладки сразу показывать последнее успешно загруженное состояние. Нельзя сначала показывать пустой экран, а затем заменять его данными.
- После первого отображения выполнять тихое фоновое обновление без перерисовки, если данные не изменились.
- Левая карточка называется `Факт`: общее количество лидов, обычные лиды, реклама, факт/план и показатели менеджеров.
- Правая карточка называется `План`, основной показатель внутри — `Квота`; ниже показывать квоты менеджеров.
- Центральный график должен занимать всё доступное пространство и включать даты текущей недели до ближайшего четверга включительно.
- Сохранить режимы `Линия`, `Столбцы`, `По людям`. Активная кнопка — светло-голубая, в стиле кнопки `Сохранить неделю`.
- Все функции существующего дашборда лидов, ручное сохранение недели и пользовательские данные сохранить.

## 4. Продажи

- Слева показать `Факт`: общую сумму и суммы Анны, Георгия и Виталия.
- Ниже разместить блок `КП`. Итоговое количество сделать заметным, но со спокойной голубой заливкой. Показатели Анны, Георгия и Виталия сделать компактнее и добавить между ними достаточно воздуха.
- В центре оставить график продаж с переключателем `Недели / Месяц`.
- Справа показать `Квота`: общую сумму, затем квоты Анны, Георгия и Виталия.
- Под квотами вывести проекты Анны и Георгия отдельно. Для каждого менеджера сначала показывать три самых крупных проекта, отсортированных от большей суммы к меньшей. Остальные открывать кнопкой `Показать ещё`.
- Не выводить служебные подписи, ссылки на таблицы и пояснения об источниках данных в пользовательском интерфейсе.

## 5. Выручка

- Использовать ту же сетку, размеры карточек, типографику и поведение, что и в продажах.
- Слева показать фактическую выручку: итог и суммы Анны, Георгия и Виталия.
- В центре — график выручки с периодами `Недели / Месяц`.
- Справа — квота выручки из рабочей таблицы, вкладка `Оплаты`.
- Проекты Анны и Георгия показывать отдельно: первые три по убыванию суммы и кнопка `Показать ещё` для полного списка.
- Не допускать появления старого демонстрационного значения перед загрузкой актуальных данных: сначала использовать кеш последней успешной загрузки.

## 6. Выработка

- Слева в карточке `Факт` крупно показать два основных показателя: общую выработку и выработку по услугам. Дополнительные показатели не выводить.
- В центре сохранить переключатель `Общая / Услуги` и `Недели / Месяц`.
- Общую выработку показывать голубым графиком, услуги — фиолетовым графиком.
- Справа в карточке `План` крупно показать общий план и план по услугам.
- Ниже вывести проекты из рабочей таблицы, вкладка `План`, отсортированные от большей общей суммы к меньшей.
- По умолчанию показывать десять самых крупных проектов. Полный список открывать кнопкой `Показать ещё`, чтобы исходная высота вкладки совпадала с продажами и выручкой.

## 8. Логика двенадцати недель

- До 1 сентября 2026 года включительно недельное окно продаж, выручки и выработки содержит 12 точек от `11.06` до `27.08`.
- Первое переключение выполняется **2 сентября 2026 года**, то есть за день до четверга `03.09`.
- После переключения первая точка — `09.07`, последняя — `24.09`.
- Далее окно сдвигается сразу на четыре недели каждые 28 дней, сохраняя ровно 12 недельных точек.
- Формула должна строить подписи дат календарно и подставлять ноль только для недель, по которым в источнике ещё нет значения.

## 9. Проверка перед публикацией

- Проверить четыре вкладки на одном разрешении: при переключении колонки и карточки не смещаются.
- Проверить загрузку из кеша без пустого состояния и обновление всех источников раз в 5 секунд.
- Изменить тестовое значение в каждой исходной таблице и убедиться, что на экране появляется новое значение без ручного обновления страницы.
- Проверить недельные и месячные графики, масштаб от нуля, отступ последней точки и подписи дат.
- Проверить сортировку проектов, лимиты `3 / 3 / 10` и работу кнопок `Показать ещё`.
- Проверить, что переходы в другие разделы ERP работают в основной оболочке и не ведут на отсутствующие локальные файлы.
